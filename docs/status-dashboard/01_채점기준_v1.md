## 판정 원칙 (v0 유지)

- 기준은 **"면접에서 버틸 만큼 충분한가"**다. 제목이나 문장이 있다는 것만으로는 채움이 아니다.
- 문서 구조에 의존하지 않는다. 칸마다 문서 **전체**에서 해당 내용을 찾고, 찾은 위치(절 이름)를 근거로 적는다.
- `주의` 절도 읽는다. 본문이 주장한 것을 `주의`가 한정·부정하면 `주의` 쪽을 따른다.
- **문서에 쓰인 수치를 그대로 믿지 않는다.** 출처·조건을 문서 안에서 되짚을 수 없는 수치는 충분함의 근거가 되지 못한다(v1 신설).

## 판정 4단계

| 판정 | 조건 | 점수 |
|---|---|---|
| 충분함 | 칸별 "충분함" 조건을 모두 만족 | 1 |
| 부족함 | 칸별 "부족함" 조건에 해당 | 0.5 |
| 비어 있음 | 칸별 "비어 있음" 조건에 해당하거나, 해당 내용이 문서 어디에도 없음 | 0 |
| 한계 명시 | 해당 내용이 **없고**, 문서가 그 내용을 "확인할 수 없다/측정하지 않았다"고 **명시** | 분모에서 제외 |

- **v0의 "내용이 일부라도 있으면 충분함/부족함" 규칙은 폐기한다.** 부족함과 비어 있음은 아래 칸별 조건으로만 가른다(v1 #1·#2).
- 채움률 = 점수 합 ÷ (7 − 한계 명시 칸 수) × 100. **가중치는 전 칸 동일**(v1 #7).

## 7개 칸

| # | 칸 | 충분함 | 부족함 | 비어 있음 |
|---|---|---|---|---|
| C1 | 어떤 문제였나 | 구체적 증상 + 영향(누가·무엇이·얼마나) + 왜 지금 풀어야 했나 | 증상은 있으나 영향의 크기나 "왜 지금" 중 하나가 없음 / 위험을 일반론으로만 서술 | 문제 서술 없음 |
| C2 | 내가 한 일 | 본인 행동이 구체적이고, **본인 범위와 팀·타인 범위가 구분**돼 있다 | 행동은 구체적이나 주어가 없어 본인 몫을 알 수 없음 | 행동 서술 없음 |
| C3 | 문제 해결 방식 | **검토한 대안 하나 이상**과, 그 대안 대신 이 방식을 고른 이유(트레이드오프)가 있다 (v1 #5) | 선택 이유나 원인 분해는 있으나 **대안 비교가 없음** — "다른 방법은요?"에 답할 수 없음 | 최종 설계만 있고 이유도 없음 |
| C4 | 측정 방식 정의 | 결과 지표를 **무엇을·어떤 조건에서(기간·대상)·무엇을 분모로** 쟀는지 정의돼 있고, 출처를 문서 안에서 되짚을 수 있다 (v1 #3) | 지표는 정의됐으나 조건·분모·출처 중 일부가 없음 | **검증 절차(테스트·체크리스트)만 있고 성과 측정 정의는 없음** (v1 #2) / 측정 서술 없음 |
| C5 | 결과 KPI | 운영 효과 KPI가 **before→after 둘 다** 있고, 각 수치의 출처를 되짚을 수 있다 | 운영 효과 KPI이지만 한쪽 값만 있음 / 값이 정밀하지 않음("수 일→수 시간") / 출처를 되짚을 수 없음 | **정성 결과만** / **구조·산출물 수치만**(파일·화면·테이블 수) / **노력량만**(커밋·라인 수·소요일) (v1 #1) |
| C6 | 왜 대단한가 | 난이도·리스크·규모를 **비교 맥락**과 함께 설명(실패하면 무슨 일이 났나, 무엇이 어려웠나) | "중요했다" 수준의 주장, 또는 가정적 위험만 있고 난이도·규모가 없음 | 서술 없음 |
| C7 | 데이터 문해력 | **데이터를 보고 내린 결정**과 그 데이터가 있다(예: 회귀 결과 N건 중 N건 통과를 보고 배포 결정, 로그 분포를 보고 임계값 설정) (v1 #6) | 데이터 기반 결정은 없으나 **해석 함정을 인지하고 다룸**(분모 오염·합산 수치·상관≠인과) | 둘 다 없음. 출처 표기(근거 위생)만 있는 경우 포함 |

### C4·C5 감점 귀속 (v1 #4)

같은 수치의 결함을 두 칸에서 이중으로 깎지 않는다.

| 결함 | 깎는 칸 |
|---|---|
| 값이 정밀하지 않음, 한쪽 값만 있음 | C5만 |
| 측정 조건(기간·대상)·분모가 없음 | C4만 |
| 출처를 되짚을 수 없음 | C4·C5 각각 상한이 부족함 (수치 자체의 신뢰 문제라 양쪽 모두 해당) |

### C5 내용 유형 예시 (v1 #1)

⚠️ 첫 행의 수치는 형식을 보여주려고 만든 **가상 예시**다. 실제 프로젝트 수치가 아니다.

| 서술 | 유형 | C5 판정 |
|---|---|---|
| "온보딩 3일 → 2시간 (기간 X, 신규 기관 N곳, 요청~완료 시각 기준)" — 가상 예시 | 운영 효과 KPI, 양쪽 값, 출처 있음 | 충분함 후보 |
| "온보딩 수 일 → 수 시간" | 운영 효과 KPI, 정밀하지 않음 | 부족함 |
| "JSP 6개 → 동적 사이드바 1개" | 구조·산출물 수치 | 비어 있음 |
| "커밋 72건, 2주 소요" | 노력량 | 비어 있음 |
| "사이드바가 DB 주도로 전환됐다" | 정성 결과 | 비어 있음 |

```
|---|---|---|---|---|
| C1 | ... | ... | ... | ... |
```

### 출력 규칙 — 사람 이름 금지 (v1 #8)

- 이유·근거 위치·채우기 질문에 **사람 이름을 쓰지 않는다.** 문서에 이름이 있어도 "담당 팀원", "팀원", 위키 별칭(팀원A~H) 중 문서에 이미 쓰인 표기로만 부른다
- 구현 요건: 채점 결과를 화면·파일에 쓰기 전에 이름 검사를 통과시킨다. 위키 `check.py`는 한국어 이름 패턴이 없어 이 검사를 대신하지 못한다(2026-11-15 확인) — 별도 검사가 필요하다
- 회귀 테스트 케이스: 문서 표 안에 "담당 ○○○"(한국어 성+이름 3자)가 있을 때, C2 채우기 질문에 그 이름이 나오지 않아야 한다(2026-11-15 R-A 사고 재현)

## v1에서 알려진 약점 (재테스트 전 예측)

- C3 대안 필수화로 **대부분의 문서가 C3 부족함**으로 떨어질 수 있다 — 위키 문서가 대안 비교를 적어 두는 관행이 없었기 때문. 재테스트에서 C3 충분함 비율을 본다
- C7 "데이터 기반 결정"의 경계(로그로 원인을 추적한 것은 결정인가?)가 새 불일치 지점이 될 수 있다
- 「출처를 되짚을 수 있다」의 판정 — 문서 안 근거 링크만 보고, 링크 대상은 열지 않는 것이 v0 채점 지시였다. 링크만으로 출처 확인을 인정할지 재테스트에서 관찰한다
