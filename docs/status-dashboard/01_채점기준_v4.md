## 판정 원칙 (v0 유지)

- 기준은 **"면접에서 버틸 만큼 충분한가"**다. 제목이나 문장이 있다는 것만으로는 채움이 아니다.
- 문서 구조에 의존하지 않는다. 칸마다 문서 **전체**에서 해당 내용을 찾고, 찾은 위치(절 이름)를 근거로 적는다.
- `주의` 절도 읽는다. 본문이 주장한 것을 `주의`가 한정·부정하면 `주의` 쪽을 따른다.
- **문서에 쓰인 수치를 그대로 믿지 않는다.** 출처·조건을 문서 안에서 되짚을 수 없는 수치는 충분함의 근거가 되지 못한다(v1 신설).
- **칸을 보기 전에 문서 유형을 정한다 (v4 #1).** 문서의 중심이 무엇인지로 하나만 고른다.
  - **프로젝트** — 무언가를 만들거나 고친 작업이 중심인 문서(사고가 계기여도 본문이 만든 것·고친 것이면 프로젝트)
  - **장애** — 서비스 중단·오류 사고의 경위·원인·대응이 중심인 문서
  - **조사** — 사실 확인·측정·비교·감사가 중심이고, 결과가 "무엇이었나/어떤 수준인가"인 문서(부하 테스트로 현 수준을 잰 문서 포함)

## 판정 4단계

| 판정 | 조건 | 점수 |
|---|---|---|
| 충분함 | 칸별 "충분함" 조건을 모두 만족 | 1 |
| 부족함 | 칸별 "부족함" 조건에 해당 | 0.5 |
| 비어 있음 | 칸별 "비어 있음" 조건에 해당하거나, 해당 내용이 문서 어디에도 없음 | 0 |
| 한계 명시 | 해당 내용이 **없고**, 문서가 그 내용을 "확인할 수 없다/측정하지 않았다"고 **명시** | 분모에서 제외 |

- **v0의 "내용이 일부라도 있으면 충분함/부족함" 규칙은 폐기한다.** 부족함과 비어 있음은 아래 칸별 조건으로만 가른다(v1 #1·#2).
- **한계 명시는 작성자 본인의 작업에 대해서만 (v4 #2):** "내가 측정하지 않았다/확인할 수 없었다"처럼 문서 작성자 쪽 작업의 내용이 없다고 밝힌 경우만 인정한다. "이 설정을 왜 골랐는지 기록에 없다"처럼 타인의 과거 결정에 대한 공백은 한계 명시가 아니다 — 해당 칸은 문서에 있는 내용으로 판정한다.
- **한계 명시는 칸 단위 (v3 #1):** 문서의 한계 문장이 **어느 칸의 내용**이 없다고 말하는지 보고, 그 칸에만 한계 명시를 준다. 한 문장으로 두 칸을 동시에 한계 명시로 만들지 않는다(그 문장이 두 칸의 내용을 각각 명시적으로 부정할 때만 예외).
- **C5 한계 명시 범위 (v2 #2):** 주 KPI가 없다고 명시했을 때, 문서에 남은 수치가 운영 효과 KPI가 아니면(검증 결과·벤치마크·구조 수치·노력량) 한계 명시로 본다. 남은 수치가 운영 효과 KPI면 한계 명시가 아니라 그 수치로 충분/부족을 판정한다.
- 채움률 = 점수 합 ÷ (7 − 한계 명시 칸 수) × 100. **가중치는 전 칸 동일**(v1 #7).
- **채움률은 스크립트가 계산한다 (v2 #7).** 채점자(LLM)는 칸별 판정만 낸다. 채점자가 퍼센트를 적더라도 집계에 쓰지 않는다.

| C7 | 데이터 문해력 | **데이터를 보고 내린 결정**과 그 데이터가 있다(예: 회귀 결과 N건 중 N건 통과를 보고 배포 결정, 로그 분포를 보고 임계값 설정) (v1 #6). 데이터와 다른 이유가 섞였다면 **둘을 어떻게 저울질했는지**가 적혀 있어야 한다(v2 #5) | 데이터 기반 결정은 없으나 **해석 함정을 인지하고 다룸**(분모 오염·합산 수치·상관≠인과) / 데이터는 제시됐으나 결정 이유가 데이터 외 이유뿐(v2 #5) | 둘 다 없음. 출처 표기(근거 위생)만 있는 경우 포함 |

### 문서 유형별 읽는 법 (v4 #1)

위 표가 **프로젝트** 유형의 기본이다. 장애·조사 유형은 아래 행이 C1·C3·C4를 대신한다. C2·C5·C6·C7은 모든 유형에서 위 표 그대로다.

| 유형 | 칸 | 충분함 | 부족함 | 비어 있음 |
|---|---|---|---|---|
| 장애 | C1 | 증상 + 영향 범위(무엇이·얼마나·얼마 동안) + 원인 | 증상·영향은 있으나 원인이나 영향의 크기 중 하나가 없음 | 사고 서술 없음 |
| 장애 | C3 | 원인 분해 + **대응·재발방지에서 고를 수 있었던 다른 안과 버린 이유** | 원인 분해만 / 대책만 나열 / "검토 중"인 안만 | 대응 서술 없음 |
| 장애 | C4 | 발생·감지·복구 시각과 그 출처 **+ "발생"·"복구"를 무엇으로 판정했는지**(v4 #1-b) | 시각·지속 시간만 있고 판정 기준이 없음 / 출처 일부 없음 | 시각 서술 없음 |
| 조사 | C1 | **무엇이 불확실했나** + 그 불확실성이 어떤 판단(서술·결정·위험)에 영향을 주나 | 조사 대상은 있으나 왜 확인해야 했는지가 없음 | 없음 |
| 조사 | C3 | 확인 방법 + **다른 확인 방법과 그 방법을 버린 이유**(예: 저장소로는 구분 불가 → 콘솔 직접 조회) | 확인 방법만 있음 | 확인 방법 서술 없음 |
| 조사 | C4 | 조사 대상·**시점**·분모·출처가 있음. 부하 테스트면 표본 규모까지(v4 #1-c) | 일부 없음 | 없음 |

- **벤치마크 수치는 유형과 무관하게** C4 근거로 쓸 때 표본 규모(반복 횟수·요청 수)가 있어야 충분함이다(v4 #1-c). 프로젝트 문서의 구성 간 비교도 같다.
- 유형이 애매하면 "애매했던 이유"에 적고, 문서의 **본문 분량이 가장 많은 쪽**으로 고른다.

### C4·C5 감점 귀속 (v1 #4)

같은 수치의 결함을 두 칸에서 이중으로 깎지 않는다.

| 결함 | 깎는 칸 |
|---|---|
| 값이 정밀하지 않음, 한쪽 값만 있음 | C5만 |
| 측정 조건(기간·대상)·분모가 없음 | C4만 |
| 출처를 되짚을 수 없음 | C4·C5 각각 상한이 부족함 (수치 자체의 신뢰 문제라 양쪽 모두 해당) |

### C5 내용 유형 예시 (v1 #1)

⚠️ 첫 행의 수치는 형식을 보여주려고 만든 **가상 예시**다. 실제 프로젝트 수치가 아니다.

| 서술 | 유형 | C5 판정 |
|---|---|---|
| "온보딩 3일 → 2시간 (기간 X, 신규 기관 N곳, 요청~완료 시각 기준)" — 가상 예시 | 운영 효과 KPI, 양쪽 값, 출처 있음 | 충분함 후보 |
| "온보딩 수 일 → 수 시간" | 운영 효과 KPI, 정밀하지 않음 | 부족함 |
| "JSP 6개 → 동적 사이드바 1개" | 구조·산출물 수치 | 비어 있음 |
| "커밋 72건, 2주 소요" | 노력량 | 비어 있음 |
| "사이드바가 DB 주도로 전환됐다" | 정성 결과 | 비어 있음 |

| "재처리 N건 중 M건 결과 변경" | **검증 결과** (v2 #2) | 비어 있음. 주 KPI 없음을 명시했다면 C5 한계 명시 |

## 출력 형식

```
## <문서명>
유형: <문서명> = 프로젝트|장애|조사
| 칸 | 판정 | 근거 위치 (절 이름) | 이유 (부족·비어 있음이면 필수) | 채우기 질문 (부족·비어 있음이면 필수) |
|---|---|---|---|---|
| C1 | ... | ... | ... | ... |
```

- **채점자는 채움률·점수 합을 쓰지 않는다 (v2 #7).** 판정 표만 낸다
- 표시 단계(대시보드)는 스크립트가 판정에서 `채움률 N% (점수 합 X / 분모 Y, 한계 명시 Z칸)`을 계산해 함께 보여준다 — 셋을 항상 같이 쓴다(v1 #9)

### 출력 규칙 — 사람 이름·식별자 금지 (v1 #8, v2 #6)

- 이유·근거 위치·채우기 질문에 **사람 이름을 쓰지 않는다.** 문서에 이름이 있어도 "담당 팀원", "팀원", 위키 별칭(팀원A~H) 중 문서에 이미 쓰인 표기로만 부른다
- **지원 회사명·티켓 번호·테이블명·코드 식별자(클래스·메서드명)도 인용하지 않는다 (v2 #6).** 근거 위치는 **절 이름**으로만 가리킨다(예: 「설계 판단」). 내용을 설명해야 하면 일반어로 바꾼다(예: "메뉴 테이블", "공용 HTTP 유틸")
- 구현 요건: 채점 결과를 화면·파일에 쓰기 전에 이름 검사를 통과시킨다. 위키 `check.py`는 한국어 이름 패턴이 없어 이 검사를 대신하지 못한다(2026-11-15 확인) — 별도 검사가 필요하다
- 회귀 테스트 케이스: 문서 표 안에 "담당 ○○○"(한국어 성+이름 3자)가 있을 때, C2 채우기 질문에 그 이름이 나오지 않아야 한다(2026-11-15 R-A 사고 재현)
