## 이번 감사에서 얻은 교훈 — 세 번째 계산 오류

이번 실험에서 계산 오류가 세 번 나왔다. 모두 LLM이 판정에서 채움률을 합산하다 틀렸다.

| 누가 | 무엇을 | 틀린 값 | 맞는 값 |
|---|---|---|---|
| 채점자 B-1 | d1 C7을 부족함으로 볼 때의 채움률 | 39.3% | 42.9% (3.0/7) |
| 채점자 R-G | doc_P C5를 부족함으로 볼 때의 채움률 | 75.0% | 71.4% (5.0/7) |
| Codex 감사자 | R-G P, R-H P·Q, B-1 d4 채움률 | 64.3%·64.3%·78.6% | 78.6%·71.4%·85.7% |

판정(칸별 충분·부족·비어 있음)은 채점자 간 일치율이 높았지만, **판정에서 퍼센트를 계산하는 산술은 채점자도 감사자도 틀렸다.** 대시보드 구현 요건으로 확정한다: **LLM은 칸별 판정만 내고, 채움률은 스크립트가 계산한다.** 감사도 마찬가지로 수치 검증은 스크립트로 한다 — 이번에 기각 판단을 스크립트 재계산으로 내린 것처럼.
