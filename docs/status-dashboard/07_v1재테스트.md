### 블라인드 — 새로 드러난 C5의 경계 (새 문서에서만 나옴)

1. **d4 — 벤치마크 비교 수치는 어느 유형인가.** 문서에는 "OTel vs Direct" 부하 테스트 결과(P99·처리량)가 있다. 이건 도입 전→후 운영 효과가 아니라 **두 구성의 비교**다. B-1은 부족함, B-2·B-3은 비어 있음. v1의 C5 유형표(운영 효과 KPI / 구조 수치 / 노력량 / 정성 결과)에 **"구성 간 벤치마크" 유형이 없다** → v2 후보
2. **d3 — 대체 지표가 있을 때의 한계 명시.** 문서는 처리 시간 전후 수치가 없다고 명시하면서, 정확도 지표(재채점 504건 중 11건 변경)를 갖고 있다. B-1·B-2는 한계 명시, B-3은 "대체 수치가 있어 분모에서 빼지 않음 → 부족함". **한계 명시 판정이 '칸 전체'에 대한 것인지 '주된 KPI'에 대한 것인지** 기준이 정하지 않았다 → v2 후보
3. **d3 C3 — "기한 내 순차 처리 불가"를 대안 비교로 볼 것인가.** B-1만 충분함. 대안 필수화(v1 #5)의 경계 사례 — "기존 방식이 불가능했다"는 대안 비교인가
4. **d3 C4 — 분모가 맞지 않는 측정 정의** (Codex 감사 중-8 반영, 채점자 원본 「애매했던 이유」에서 누락됐던 것). 정확도 지표의 대상 127명 × 4문항 = 508인데 분모는 504건이고, "점수 변경"의 비교 기준(원 채점값 대비 무엇)과 측정 시점이 없다. 3명 모두 부족함으로 일치했지만, **분모 불일치가 해명되지 않은 지표를 v1 C4의 "분모 정의됨"으로 볼지** 기준이 정하지 않았다 → v2 후보
5. **d4 C7 — 데이터 근거와 비데이터 근거가 섞인 결정** (Codex 감사 중-8 반영). 구성 선택에 P99·처리량 데이터와 "표준화·벤더 독립성" 같은 비데이터 이유가 함께 있다. 선택된 쪽(OTel)은 최대 처리량에서는 오히려 열세다. 3명 모두 충분함으로 봤지만 B-2·B-3이 경계로 기록했다. **데이터가 결정에 어느 정도 기여해야 "데이터 기반 결정"인지** 기준이 없다 → v2 후보

### 회귀 — 해석 단서

- **doc_K의 하락폭(64.3 → 35.7, −28.6%p)에는 채점자 편차가 섞였다.** KPI 삭제로 예상되는 하락은 C4·C5 각 0.5 → 0, 즉 −14.3%p다. 나머지 −14.3%p는 G-1이 C3·C6을 블라인드 3명과 달리 부족함으로 본 탓이다(같은 내용인 doc_M에서 G-2는 C3·C6 충분). 하향 감지 통과 조건(C5 비어 있음 + 기준선보다 낮음)은 이 편차를 빼도 충족된다
- **doc_N은 v0 대비 C7이 한 단계 높다**(d1 기준선 비어 있음 → doc_N 부족함). 원문은 같은데 G-2가 "역산으로 단정하면 안 된다"를 해석 함정으로 인정했다. C7의 "해석 함정"과 "근거 위생" 경계는 v1에서도 개별 채점자 수준에선 여전히 흔들린다(블라인드에서는 3명 일치였다)
- **doc_K 이름 검사의 강도**: G-1 출력에 이름이 0회였지만, 채점 이유에 담당자 행을 인용하지 않았으므로 "이름을 쓸 상황에서 참았다"는 증거는 아니다. v1 #8 검증은 **약한 통과**로 기록한다
