# 블라인드 테스트 — 기준만 주면 다른 채점자도 같은 판정을 내리는가

> 2026-11-15. 기준 v0이 **채점자에 따라 흔들리지 않는지** 확인한다. 대시보드는 매번 새 LLM 세션이 채점하므로, 기준만 보고 같은 결론이 나와야 퍼센트를 믿을 수 있다.

## 설계

- 채점자 3명: 메인 세션(수기, `02_수기채점.md`) + 독립 서브에이전트 R-A, R-B
- R-A·R-B에게 준 것: 기준 파일(`01_채점기준_v0.md` 사본), 원본 두 문서의 사본(파일명 orig_1·orig_2). 채점자마다 별도 폴더
- 주지 않은 것: 수기 채점 결과, 대화 맥락(사용자 체감 "80% 정도·KPI 부족"), 다른 채점자의 결과. 문서 안 링크 대상도 열지 말라고 지시
- 지시문은 R-A·R-B 동일(회귀 채점자 R-C·R-D와도 폴더·파일명만 다르고 동일)

## 측정 지표

- **칸별 완전 일치율**: 14칸(2문서 × 7칸) 중 3명 판정이 모두 같은 칸의 비율
- **다수결 일치율**: 3명 중 2명 이상 같은 칸의 비율
- **채움률 편차**: 문서별 3명 채움률의 최대−최소

## 사전 예측 (채점 실행 전 고정)

| 항목 | 예측 | 근거 |
|---|---|---|
| 완전 일치율 | 9/14 (64%) 안팎 | 판정이 4단계라 "부족함 ↔ 충분함" 경계에서 갈릴 칸이 있다 |
| 가장 흔들릴 칸 | C7(데이터 문해력), C2(내가 한 일) | C7은 정의가 흐리다. C2는 권한재설계 문서에 주어가 없어 엄격도에 따라 갈린다 |
| 흔들리지 않을 칸 | NL2SQL의 C4·C5(비어 있음), 권한재설계의 C1(충분함) | 내용 유무가 명확하다 |
| 채움률 편차 | 문서별 15%p 이내 | 이걸 넘으면 대시보드 퍼센트를 신뢰할 수 없다 |

## 통과 기준

- 다수결 일치율 12/14 이상, **그리고** 문서별 채움률 편차 15%p 이내
- 통과 못 하면 가장 많이 갈린 칸의 정의를 고쳐 v1로 올리고 재테스트

## 알려진 한계

- 기준 파일의 "부족함의 전형" 열에 권한재설계 문서에서 따온 예("수 일→수 시간")와 NL2SQL 판정과 비슷한 예("기능의 출발점이 없음")가 들어 있다 — 기준 작성자가 문서를 먼저 읽고 기준을 쓴 탓이다. 블라인드 채점자가 이 예시에 끌려 수기 채점과 일치할 수 있으므로, **이 테스트의 일치율은 상한 쪽으로 편향돼 있다.** 새 문서(이 두 문서가 아닌 것)로 재테스트해야 기준의 일반성이 확인된다
- 채점자가 모두 같은 계열 모델이라 모델 고유의 편향은 걸러지지 않는다

**판정: 통과.** 다만 해석에 아래 단서가 붙는다.

### 해석

1. **관찰: 불일치 3칸은 전부 메인 세션의 판정이 독립 채점자 둘보다 낮았다.** 독립 채점자 둘은 14칸 전부 같았다. 해석은 칸마다 다르다 (Codex 감사 중-1 반영 — 초판은 "흔들린 것은 기준이 아니라 작성자의 해석"이라고 단정했으나 C7에는 그 단정이 성립하지 않는다)
   - **C3 (NL2SQL)** — 기준 문구는 "원인을 쪼갠 흔적 **또는** 대안과 선택 이유". 메인은 "대안 비교가 없으면 부족"으로 읽었고, R-A·R-B는 "위협별 분해 + 선택 이유"로 충족이라 읽었다. **기준 문구의 `또는`에 비추면 메인이 기준보다 엄격했다** — 이 칸은 작성자 해석 문제로 볼 근거가 있다
   - **C7 (두 문서 모두)** — 기준은 "분모 오염·상관≠인과·합산 수치 등 해석 함정을 인지하고 **다뤘다**"면 충분. R-A·R-B는 "72커밋은 합산 수치라 이 프로젝트 규모로 쓰지 않는다"를 함정 인지로 봤고, 메인은 "근거 위생(출처 표기)"으로 봤다. **기준 문구만으로는 어느 쪽이 맞는지 확정되지 않는다** — 기준이 "근거 위생"과 "해석 함정을 다룸"의 경계를 정의하지 않았기 때문이다. C7 기준 적합성은 **미확정**이며 v1 #6에서 사용자가 정한다
2. **예측이 틀린 곳**: C2가 흔들릴 거라 예측했으나 3명 모두 같았다(NL2SQL 충분, 권한재설계 부족). "본인 범위 구분"이라는 조건이 명확해서다. 대신 예측 못 한 C3가 흔들렸다
3. **NL2SQL 편차 14%p는 경계선이다.** 메인 1명이 빠지면 0%p이므로 기준 자체의 재현성은 높다. 하지만 "기준 작성자 본인도 기준과 다르게 읽는다"는 것은 C3·C7 문구가 해석 여지를 남긴다는 뜻이다 → v1에서 문구 보강 대상
4. **C7이 가장 흔들린다는 예측은 맞았다** (3칸 중 2칸이 C7)

### 채점자들이 스스로 짚은 기준 결함 (「애매했던 이유」에서 수집)

| 지적 | 제기한 채점자 | 내용 |
|---|---|---|
| C4·C5 중복 감점 | R-A, R-B | 같은 "수 일→수 시간" 하나가 C4(정의 없음)와 C5(정밀도 부족)에서 두 번 깎인다 |
| C3 "대안 비교" 요구 여부 | R-A, R-B | 대안 비교를 엄격히 요구하면 부족, 선택 이유만으로 보면 충분 — 기준이 어느 쪽인지 명확하지 않다 |
| C7 "또는" 조건 | R-A, R-B | 데이터 기반 판단 없이 함정 인지만으로 충분을 주는 것이 맞는가 |
| C6 비교 맥락의 엄격도 | R-B | "실패하면 전 사용자 접근 불가" 같은 가정적 서술을 비교 맥락으로 인정하는 것이 관대할 수 있다 |
| C2 QA 행동의 서술 수준 | R-A | 범위 구분은 명확하나 QA에서 무엇을 했는지는 얇다 |

### 부수 발견 — 원본 위키의 마스킹 위반이 채점 출력으로 전파됨

- `위키/기관기반-권한재설계.md` 59행 일정 표에 **동료 실명**("담당 ○○○")이 있다 — 위키 규칙 1(마스킹) 위반
- R-A가 이 이름을 C2 채우기 질문에 그대로 인용했다. 대시보드·`/status`가 채우기 질문을 화면에 띄우면 **원본의 실명이 새 산출물로 복제된다**
- 조치: 기록 사본(`채점자원본/R-A_블라인드.md`, `fixtures/doc_A.md`)은 `[팀원·마스킹]`으로 가렸다. **위키 원본은 요청 범위 밖이라 고치지 않았고 사용자에게 보고했다**
- 재검증 경로(Codex 감사 중-4 반영): 마스킹 전 원본 출력은 세션 scratchpad의 `rubric-test/ra/result.md`(휘발성, 세션 종료 시 소멸)에 있었다. 실명 포함 사실은 메인 세션이 사본 생성 직후 `grep -rn`으로 확인했다 — R-A 사본 25행, doc_A 사본 59행 2건. 기록 폴더에는 실명을 다시 남기지 않으려고 원본을 보관하지 않았으므로, **이 기록만으로 전파 사실을 재검증할 수는 없다**
- 설계 시사점: 채점 출력에 실명·식별자 검사가 필요하다. 단 **위키 `check.py`는 한국어 이름 패턴이 없어 이 실명을 잡지 못한다**(2026-11-15 실행 확인 — 검사 패턴은 이메일·IP·AWS ID·리소스 이름뿐). 기존 도구로 막을 수 없다는 뜻이다 → v1 #8
