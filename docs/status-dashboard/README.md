# 위키 상태 대시보드 — 기획·채점 기준 검증 기록

> 이슈: [#14 상태 대시보드](https://github.com/LEEHYUNBOK/chwijun-copilot/issues/14) · 관련 [#15 설명 가능성 테스트](https://github.com/LEEHYUNBOK/chwijun-copilot/issues/15) · [#16 직군별 채점](https://github.com/LEEHYUNBOK/chwijun-copilot/issues/16) · [#17 지원현황·포트폴리오(후속)](https://github.com/LEEHYUNBOK/chwijun-copilot/issues/17) · **[#18 채점 기준 v1 개정](https://github.com/LEEHYUNBOK/chwijun-copilot/issues/18)**
> **공개본이다.** 채점 대상은 개발자 본인의 경력 위키 문서 2개(LLM 생성 SQL 검증 기능 / 권한·메뉴 재설계)다. 방법·기준·판정·결과·감사 내역은 전부 여기 있고, **위키 원문이 통째로 들어간 `채점자원본/`·`fixtures/`는 공개하지 않고 개인 저장소에 보관**한다(사내 시스템 세부가 들어 있다). 본문에서 그 경로를 가리키는 곳은 비공개 보관본을 뜻한다.

## 지금까지 합의된 설계 (브레인스토밍, 2026-11-12 ~ 11-15)

| 항목 | 결정 | 결정 주체 |
|---|---|---|
| 해결할 문제 | 위키에 쌓다가 "다 쌓았나? 뭐가 부족하지?"를 판정할 기준이 없다. 지금은 md를 전부 다시 읽어야 한다 | 사용자 |
| 채움 판정 기준 | 제목·문장이 있는 것이 아니라 **면접에서 버틸 만큼 충분한가** | 사용자 |
| 칸 구성 | 문제 / 내가 한 일 / 문제 해결 방식(맥킨지식 구조화) / 측정 방식 정의 / 결과 KPI / 왜 대단한가 / 데이터 문해력 | 사용자 (항목), 메인 세션 (7칸 정리) |
| 채우는 방식 | `/chwijun-copilot:status` → 부족한 칸마다 질문 하나씩 → 답을 받아 위키에 반영(반영 전 확인) → 재채점. 답이 없으면 비워 둔다 | 사용자 (방식), 메인 세션 (이름·확인 절차) |
| 첫 버전 범위 | 위키 채움 상태만. 지원현황 지표·포트폴리오 보기는 #17로 미룸 | 사용자 |
| 구현 형태 | 웹서비스가 아니라 **정적 HTML + JSON**. 채점은 LLM(바뀐 문서만), 표시는 스크립트. 부족 칸 옆에 "명령어 복사" 버튼 | 메인 세션 판단 (근거는 대화 기록) |
| 대상 위키 | 개발자 본인 위키 먼저, 플러그인 사용자 위키(wiki-bootstrap 양식) 일반화는 나중 | 사용자 |
| 판정 단계 | 충분함 / 부족함 / 비어 있음 / **한계 명시**(분모 제외) | 메인 세션 제안 |
| 채점 대상 | 프로젝트·장애 문서만. 개요·정정이력 등 목차·기록 문서는 제외 | 메인 세션 제안 |
| 최종 검증 | Codex | 사용자 |
| C3 대안 비교 | **필수** — 면접의 "다른 방법은요?"에 답할 수 있어야 함 (2026-11-15) | 사용자 (추천 수용) |
| C7 데이터 판단 | **데이터 기반 결정 필수**, 해석 주의만이면 부족함 (2026-11-15) | 사용자 (추천 수용) |
| 가중치 | **동일 유지**, 문서 5~10개 추가 채점 후 재검토 (2026-11-15) | 사용자 (추천 수용) |
