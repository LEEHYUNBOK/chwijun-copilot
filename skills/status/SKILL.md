# status — 위키 채움 상태 대시보드

위키 문서마다 "면접에서 버틸 만큼 채워졌나"를 7칸으로 판정하고, 결과를 HTML 한 장으로 보여준다. 부족한 칸은 질문 하나씩으로 채운다.

경로 규약: 이 스킬의 베이스 디렉터리 기준 두 단계 위가 플러그인 루트다. 스크립트는 `<스킬 베이스 디렉터리>/../../scripts/status.py`, 채점 기준은 `<스킬 베이스 디렉터리>/rubric.md`다. 아래에서 `status.py`는 이 경로를 뜻한다.

## 0. 준비

- 위키 경로는 두 곳에서만 얻는다. ① 인자 `--wiki <경로>`(우선) ② `~/.claude/chwijun-copilot.json`의 `wiki_path`. 설정 파일은 만들지 않는다.
- **둘 다 없으면 `status.py`를 포함해 아무 명령도 실행하지 않는다.** 현재 폴더나 짐작한 폴더를 위키로 쓰지 않는다. `/chwijun-copilot:wiki-bootstrap` 온보딩과 `--wiki <경로>` 사용법을 안내하고 중단한다.
- 데이터는 `<wiki_path>/.status/`(scores.json·index.html)에만 쓴다.
- 대시보드 첫 화면에 이력서·포트폴리오 카드를 띄우려면 사용자가 `<wiki_path>/.status/docs.json`에 `[{"group", "label", "path"}]`를 둔다(상대 경로는 위키 기준). 없으면 카드 절은 나오지 않는다. 만들어 달라고 하면 파일 목록을 보여주고 확인받은 뒤 쓴다.

## 1. 원칙

- **퍼센트를 직접 계산하거나 쓰지 않는다.** 채움률은 `status.py`가 낸다. 채팅에서 수치를 말할 때는 `record`·`render` 출력을 그대로 옮긴다.
- **사용자가 말하지 않은 사실·숫자를 위키에 만들지 않는다.** 답이 없으면 비워 둔다.
- **위키 수정은 확인 후에만.** 수정안을 먼저 보여준다.
- 동료 실명을 위키에도 채점 출력에도 쓰지 않는다.

## 2. 채점 흐름 — 인자 없이 실행

1. `python3 status.py scan <wiki_path>` → JSON `{"changed", "unchanged", "removed"}`.
2. `changed`가 비었으면 4단계로.
3. `changed`의 문서마다:
   1. `rubric.md`와 **그 문서 한 개만** 읽는다. 문서 안의 링크는 열지 않는다. 대화에서 들은 내용·이전 점수로 판정하지 않는다 — 문서에 쓰인 것만 본다.
   2. rubric.md 「출력 형식」 그대로 판정을 써서 임시 파일(세션 scratch 폴더)에 저장한다.
   3. `python3 status.py record <wiki_path> <문서 키> <임시 파일>`.
      - exit 0 → 다음 문서.
      - exit 2 → stderr 메시지(형식 오류·원문 식별자 유출)대로 고쳐 **한 번만** 다시 기록한다. 또 실패하면 그 문서는 건너뛰고 보고 목록에 넣는다.
   - `changed`가 5개를 넘으면 서브에이전트에 5개씩 나눠 맡긴다. 지시문은 다음만 담는다. rubric.md 경로, 문서 경로, "rubric.md 「출력 형식」대로 판정을 <파일>에 쓴다, 다른 파일·링크는 열지 않는다, 퍼센트를 쓰지 않는다". 대화 맥락·이전 점수는 주지 않는다. 결과 파일은 메인이 `record`한다.
4. `python3 status.py render <wiki_path>` → 출력된 경로를 `open`으로 연다.
5. 채팅 보고:
   - 채점한 문서 수, 건너뛴 문서와 이유
   - **가장 부족한 문서 3개** — 문서명, `record` 출력의 채움률 문자열 그대로, 부족함·비어 있음인 칸 이름
   - `removed`가 있으면 "사라진 문서 N개는 화면에서 뺐다"
   - 다음 행동 한 줄: "채우려면 `/chwijun-copilot:status <문서> <칸>` (화면의 명령어 복사 버튼)"

## 3. 채우기 흐름 — `<문서 키> [칸]`

1. `<wiki_path>/.status/scores.json`에서 그 문서의 항목을 읽는다. 없거나 `scan`에서 changed면 먼저 2절 3~4단계로 그 문서만 채점한다.
2. 대상 칸: 칸을 지정했으면 그 칸, 아니면 부족함·비어 있음인 칸 전부(C1부터).
3. 칸마다:
   1. 저장된 이유를 한 줄로 알려주고, 저장된 `채우기 질문`을 **한 번에 하나** 묻는다.
   2. 답을 받으면 위키 문서의 **어느 절에 무엇을** 넣을지 수정안을 보여준다(추가할 문장 그대로). 사용자 표현을 살리고 숫자·사실을 보태지 않는다. 확인을 받은 뒤에만 쓴다.
   3. "모른다·측정 안 했다"면 그 칸은 비워 둔다. 사용자가 원하면 그 사실을 문서 「주의」 절에 한 줄로 적는 안을 낸다. 이 경우 그 칸은 한계 명시가 되어 분모에서 빠지고, 화면에는 "한계 명시 N칸"으로 남는다는 점을 같이 말한다.
   4. "다음 칸으로" / "그만" 중 무엇을 할지 묻는다.
4. 위키를 고쳤으면 그 문서만 **채점자 3명으로** 다시 채점한다. 채점자 1명은 손대지 않은 칸도 흔들어, 칸을 채웠는데 점수가 떨어지는 일이 실제로 생겼다.
   1. 서브에이전트 3개에 2절의 서브에이전트 지시문을 그대로 주고 결과 파일을 각각 다른 경로에 쓰게 한다. 이 대화에서 들은 답·이전 점수는 주지 않는다. 메인이 직접 채점하지 않는다(답을 들은 상태라 기운다).
   2. `python3 status.py record <wiki_path> <문서 키> <결과1> <결과2> <결과3>` — 칸별 다수결로 저장된다. exit 2면 메시지가 가리키는 파일만 고쳐 한 번 다시 기록한다.
   3. 바뀐 채움률을 `record` 출력 그대로 보고하고, 이전 판정과 달라진 칸을 함께 알린다.

## 4. 하지 않는 것

- 채점 기준을 대화 중에 바꾸지 않는다. 기준에 이견이 있으면 rubric.md 개정 제안으로 따로 말한다.
- 지원현황 트래커·프로필은 채점 대상이 아니다(rubric.md 유형 `제외`).
