# wiki-bootstrap — 경력 위키 온보딩

인터뷰로 사용자의 경력 위키를 세운다. 위키는 이후 모든 스킬(공고 적합도·이력서·패턴 분석)의 정본이다.

경로 규약: 이 스킬의 베이스 디렉터리 기준 두 단계 위가 플러그인 루트다. 템플릿은 `<스킬 베이스 디렉터리>/../../templates/`에서 가져온다.

## 0. 원칙

- **확정 사실만 싣는다.** 사용자가 말하지 않은 경험·숫자를 지어내지 않는다. 비면 비워 두고 `{{추가 확인}}`으로 표시한다.
- **질문은 한 번에 하나.** 몰아서 묻지 않는다.
- **받은 자료가 진술과 모순되면 즉시 대조해 묻는다.** 자료(파일·링크)가 타인 수행으로 기록한 일을 사용자가 본인 성과라 진술해도 그대로 수용하지 않는다 — 어느 쪽이 맞는지 확인하고, 확인 전에는 자료 쪽을 따른다.
- **기존 위키 보호.** 대상 폴더가 이미 있고 비어 있지 않으면 중단하고 사용자에게 묻는다 — 덮어쓰지 않는다. `~/.claude/chwijun-copilot.json`이 이미 있으면 재온보딩인지 확인한다.

## 1. 직군 파악 (첫 질문)

위치·이름보다 먼저 직군을 묻는다. 직군이 이후 인터뷰의 소재 축을 정한다.

| 직군 | 소재 축 (대표 작업을 이 축으로 묻는다) |
|---|---|
| 개발 | 장애 대응 · 성능 개선 · 설계 결정 — "장애를 직접 수습한 적", "느린 걸 빠르게 만든 적", "구조를 바꾼 결정" |
| 기획·PM | 의사결정 · 지표 — "지표가 움직인 기획", "이해관계 조율로 일정·범위를 바꾼 결정", "요구사항을 쳐낸 기준" |
| 디자인 | 케이스 스터디 — "문제 정의 → 탐색 → 선택안 → 결과 지표", 포트폴리오 케이스 단위 |
| 마케팅·기타 | 캠페인·프로젝트 단위 — "목표 수치 → 실행 → 결과", 예산·채널 결정 |

세부 직무(백엔드/서비스기획/프로덕트디자인 등)도 이어서 묻는다. 프로필의 `직군` 절과 job-scan 필터 추천에 쓴다.

## 2. 인터뷰

직군 확정 후 순서대로 묻는다. 각 답은 바로 기록하고 다음 질문으로.

1. 이름(위키에 쓸 표기) · 위키를 만들 폴더 경로 (기본 제안: `~/경력위키`)
2. 경력 — 회사·기간·고용형태·담당 업무 (복수면 전부)
3. 대표 작업 2~4개 — 직군별 소재 축으로. 각각 **문제 상황 → 본인이 한 일 → 결과(가능하면 before→after 수치)**. 수치를 모르면 "수치 없음"으로 두고 지어내지 않는다. 경력이 두 곳 이상이면 작업·성과마다 **어느 회사의 일인지** 확인한다 — 진술에 회사명이 없으면 추측으로 붙이지 말고 묻는다. 산출량(건수·장수·커밋 수)은 직군 불문 성과가 아니라 작업량으로만 기록한다
4. 주력 스킬 — 실무에서 직접 쓴 것만, 기간과 맥락
5. 공백 — 못 해 본 것·없는 자격. "공고 매칭 때 숨기지 않기 위해" 묻는 것임을 설명한다
6. 표기 규칙 — 과장하면 안 되는 지점 (팀 프로젝트의 본인 범위 등)

## 3. 위키 생성

`<wiki_path>`에 다음을 만든다. 템플릿은 플러그인의 `templates/`에서 복사해 인터뷰 내용으로 치환한다.

```
<wiki_path>/
├── 프로필.md        # templates/프로필.md 치환 — 모든 스킬의 매칭 기준
├── 개요.md          # 진입점 인덱스 — 모든 문서를 한 줄 설명과 함께 링크
├── 지원현황.md      # templates/지원현황.md 복사 (예시 섹션은 삭제)
└── 문서/
    └── <대표작업별 1문서>.md   # templates/위키문서.md 형식
```

- 대표 작업마다 `문서/` 아래 위키 문서 1개를 만들고 프로필의 「대표 작업」에서 링크한다
- 개요.md에 전 문서를 링크한다 — 링크 안 된 문서는 고아가 된다
- 작성 후 사용자에게 프로필.md를 보여주고 수정을 받는다. **프로필이 과장됐으면 지원 실패로 돌아온다**고 안내한다

## 4. 설정 저장

`~/.claude/chwijun-copilot.json`:

```json
{ "wiki_path": "<위 폴더 절대경로>", "tracker": "local", "notion_ds_id": "" }
```

Notion 트래커를 원하면 `tracker`를 `"notion"`으로 바꾸고 `notion_ds_id`에 지원현황 DB의 data_source id를 넣으라고 안내한다 (NOTION_TOKEN 필요). 기본은 local — 추가 설정 없이 바로 쓴다.

## 5. 마무리 보고

만든 파일 목록과 다음 단계를 안내한다: 공고가 생기면 `/chwijun-copilot:job-fit <URL>`, 관심 회사를 넣으려면 `<wiki_path>/watchlist.json`(templates/watchlist.json 복사) 후 `/chwijun-copilot:job-scan`.
