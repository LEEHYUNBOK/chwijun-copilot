# job-fit — 공고 적합도 분석 & 지원현황 등록

공고 URL 하나를 받아 ① 본문 수집 → ② 요구사항 추출 → ③ 검증 프로필과 대조 → ④ 트래커 기록까지 한다.

입력: 공고 URL (필수). 없으면 URL을 묻는다.

경로 규약: 이 스킬의 베이스 디렉터리 기준 두 단계 위가 플러그인 루트다. 스크립트는 `<스킬 베이스 디렉터리>/../../scripts/`에 있다.

## 0. 원칙

- **창작 금지.** 공고 본문에서 못 뽑은 요구사항을 지어내지 않는다. 본문을 못 가져오면 그 사실을 명시한다.
- **후한 평가 금지.** 갭을 정직하게 드러낸다. 목적은 지원 실패를 줄이는 것이다.
- 프로필의 "표기 규칙"(과장 방지)을 그대로 지킨다.

## 1. 프로필 로드 (매칭 기준)

`~/.claude/chwijun-copilot.json`을 읽어 `<wiki_path>/프로필.md`를 로드한다. 이게 유일한 매칭 기준이다. 이력서를 다시 파싱하지 않는다.

설정 파일이 없으면 `/chwijun-copilot:wiki-bootstrap` 온보딩을 안내하고 중단한다.

## 2. 공고 본문 수집

**스크립트가 1순위다. curl 조합을 손으로 재구성하지 않는다.**

```bash
python3 "<스킬 베이스 디렉터리>/../../scripts/fetch_jd.py" <URL>
```

원티드(유령공고 status 체크 포함) · 사람인(쿠키 절차 포함) · 자소설닷컴 · LG Careers · Greenhouse · Ashby · greetinghr · 일반 Next.js/HTML을 처리한다. 출력 헤더의 `status`/`note` 경고를 그대로 따른다(예: 원티드 close = 등록 금지, 사람인 "og:title 토큰 없음" = 본문과 og:title이 같은 공고인지 대조).

`retrieved=false`로 exit 1이면: WebFetch를 한 번 시도해 보고, 그래도 비면 사용자에게 본문 붙여넣기를 요청한다. 창작 금지.

**greenhouse 연동 자사 도메인 예외.** URL에 `gh_jid=` 파라미터가 있으면(예: `about.daangn.com?gh_jid=…`) fetch_jd가 404를 낸다 — 바로 `curl -s https://boards-api.greenhouse.io/v1/boards/<slug>/jobs/<gh_jid>`로 상세를 받는다. slug는 watchlist에서 찾고, 없으면 사용자에게 묻는다.

추출 항목: 회사 · 직무명 · 레벨 · 요구 연차 · 근무지 · mustHave · niceToHave · 도메인 · 마감일 · 전형 절차.
**마감일이 오늘 이전이면 "경과"로 표시.** (오늘 날짜는 컨텍스트의 currentDate 사용)

## 3. 적합도 판정

프로필 vs 공고를 냉정하게 대조한다.

- `fitScore` 0-100, `fitLevel` 상/중/하
- `matched` — 실제 근거 있는 것만
- `gaps` — 부족·미보유를 구체적으로 (연차/도메인/기술/규모)
- `verdict` — 2~3문장
- `applyRecommendation` — 지원 권장 / 도전(스트레치) / 현재는 부적합
- `tailoringTips` — 지원 시 이력서에서 강조할 포인트, 갭 대응 프레이밍

기준 참고: must-have 정합도가 높고 연차가 맞으면 "지원 권장", must-have 일부가 갭이면 "도전", 연차/핵심 도메인이 근본적으로 어긋나면 "부적합".

## 4. 트래커 기록

설정의 `tracker`가 기준이다.

- `local`(기본): `<wiki_path>/지원현황.md` 맨 위(`# 지원 현황` 헤더 바로 아래)에 `## [회사] 직무명` 섹션을 추가한다. 형식은 기존 섹션과 동일 — `- 상태:` `- 링크:` `- 마감:` `- 등록: YYYY-MM-DD · 지원: -` 네 줄 + `### 적합도 분석` 본문 (templates/지원현황.md와 글자 그대로 같은 필드명).
- `notion`: `python3 "<스킬 베이스 디렉터리>/../../scripts/track_add.py" --ds <notion_ds_id> --title <직무명> --company <회사> --url <URL> [--deadline YYYY-MM-DD] [--body 본문.md]` (NOTION_TOKEN 필요). 실패하면 local로 기록하고 그 사실을 보고한다.

**본문(적합도 분석) 템플릿:**

```
**적합도 <상/중/하> · <score>/100 · <추천> [· ⚠️ 특이사항]**

**레벨** … · **요구** 경력 N년+ · **언어** … · **근무지** … · **마감** …
**도메인** …
**전형** …

---

#### 겹치는 강점
- …

#### 결정적 갭
- …

#### 판정
<verdict>

#### 지원 전략
- <tailoringTips>

> 출처: <수집 방법>. <마감/특이사항>
```

로컬 트래커는 `##`가 공고 구분자이고 `###`가 섹션 내부 제목이다 — 본문에는 `##`·`###` 헤더를 쓰지 않는다(`####`부터). 첫 줄 판정은 헤더가 아니라 굵은 글씨다.

## 5. 마무리

트래커 기록 위치와 함께 적합도·판정·핵심 갭 1~2개를 사용자에게 보고한다. 기존 트래커의 다른 공고와 순위를 비교해주면 좋다.
