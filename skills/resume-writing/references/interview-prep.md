# 면접 대비 — 이력서 역산

이력서는 면접 질문지다. 내가 쓴 문장이 그대로 질문이 되어 돌아온다.
그러니 제출 전에 직접 뽑아본다. 답이 안 나오는 문장이 있으면 **면접 준비가 아니라 이력서를 고쳐야 한다는 신호다.**

---

## 1. 질문 뽑는 규칙

이력서를 한 줄씩 훑으며 아래 트리거에 걸리는 곳마다 질문을 만든다.

| 트리거 | 나올 질문 |
|---|---|
| 숫자가 있다 | "그거 어떻게 측정했어요?" "개선 전 수치는요?" |
| 기술 이름이 있다 | "왜 그걸 골랐어요?" "다른 대안은요?" "단점은 뭐죠?" |
| "설계했다 / 주도했다" | "구체적으로 어떤 결정을 내렸어요?" "혼자 했어요?" |
| "개선했다 / 최적화했다" | "뭐가 병목이었죠?" "어떻게 확인했어요?" |
| 팀 프로젝트 | "본인 담당은 어디까지였어요?" |
| 공백기·짧은 재직 | "이 기간에 뭐 하셨어요?" "왜 그만두셨어요?" |
| 트러블슈팅 | "지금 다시 하면 다르게 할까요?" |
| AI 활용 서술 | "어디까지가 AI고 어디부터 본인 판단이었어요?" "출력을 어떻게 검증했어요?" |
| 스킬 목록의 각 항목 | 그 기술의 기본 개념 질문 |

**스킬 목록에 적은 것은 전부 물어봐도 된다는 동의서다.** 40개를 적었다면 40개를 감당해야 한다. 못 감당할 항목은 지금 지운다.

---

## 2. 답변 구조

이력서와 같은 순서로 답한다. 그래야 이력서와 답변이 어긋나지 않는다.

```
상황 (10초)  →  내 결정과 이유 (30초)  →  결과 (10초)  →  배운 것 (10초)
```

1분 안에 끝낸다. 길게 말하면 꼬리질문 받을 기회를 스스로 없앤다. 면접은 대화지 발표가 아니다.

**핵심은 두 번째 칸이다.** 무엇을 했는지가 아니라 왜 그걸 골랐는지. 대안을 검토했고 트레이드오프를 알고 있었다는 게 드러나야 한다.

## 3. 반드시 준비할 다섯 가지

1. **1분 자기소개** — 이력서 헤드라인 + 요약 태그 2개를 말로 옮긴 것
   - 면접관은 서류를 보면서 일관성을 확인한다 — 서류와 같은 경험을 중심에 두되, 서류에 못 넣은 구체 에피소드 하나를 더한다
   - 순서: 첫 문장에 직무 역량 → 근거 경험(수치 하나) → 이 회사에서의 활용 한 문장 (잡코리아 2026 가이드, https://www.jobkorea.co.kr/goodjob/tip/view?News_No=15062)
2. **대표 프로젝트 하나를 3분 / 1분 / 20초 세 버전으로** — 면접관이 주는 시간이 매번 다르다
3. **가장 크게 실패한 경험** — 반드시 온다. 남 탓 없이, 내가 뭘 잘못 판단했는지로 답한다
4. **역질문 3개** — 조사한 티가 나는 질문. "성장할 수 있나요" 같은 건 안 한 것만 못하다
5. **모르는 것을 만났을 때의 대사** — "모릅니다"로 끝내지 말고 "안 써봤는데, 제가 아는 X와 이런 점이 비슷할 것 같습니다"까지

## 4. 근거 노트

`ai-detection.md`에서 확인한 출처들을 여기 모은다.
이력서에 쓴 주장 옆에 근거 링크를 붙여두면, 배경 질문이 왔을 때 답할 거리가 생긴다. 출처 확인의 진짜 목적은 이거다.

```
주장: 최근 업계에서 X 방식이 표준으로 자리잡는 추세
근거: (링크) / 읽은 날짜 / 핵심 한 줄
면접에서 할 말: ...
```

## 5. 리허설

- [ ] 이력서 전체에서 질문 20개 이상을 뽑았다
- [ ] 답이 막히는 문장을 이력서에서 지우거나 고쳤다
- [ ] 대표 프로젝트를 소리 내어 세 버전으로 말해봤다
- [ ] 각 답변이 1분을 넘지 않는다
- [ ] 스킬 목록의 모든 항목에 기본 질문 답변이 가능하다
- [ ] 이력서에 쓴 숫자를 전부 어떻게 쟀는지 설명할 수 있다
- [ ] 공백기·이직 사유 답변을 한 문장으로 정리했다
- [ ] 역질문 3개를 준비했다
