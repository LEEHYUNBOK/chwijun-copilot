# 채용공고 맞춤 커스터마이징

하나의 이력서를 모든 공고에 내면 아무 데도 안 맞는다. 공고마다 **재배치**한다.
새로 쓰는 게 아니다. 있는 재료의 순서와 비중을 바꾸는 작업이다.

---

## 절차

### 1단계 — 공고 해부

공고를 읽고 표로 뜯는다. 원문의 표현을 그대로 옮겨 적는다.

| 구분 | 원문 표현 | 우선순위 |
|---|---|---|
| 필수 자격 | | 상 |
| 우대 사항 | | 중 |
| 주요 업무 | | 상 |
| 인재상·팀 소개 | | 하 |

**주요 업무를 필수 자격보다 무겁게 본다.** 자격 요건은 인사팀이 쓰고, 주요 업무는 현업이 쓴다. 실제 면접관은 후자를 보고 판단한다.

우선순위는 **공고에서 반복된 횟수**로 매긴다. 세 군데에 나오는 키워드가 진짜 요구사항이다.

### 2단계 — 매칭 테이블

공고 요구사항마다 내 경험을 붙인다.

| 요구사항 | 내 경험 | 증거 (숫자·산출물) | 강도 |
|---|---|---|---|
| 대용량 트래픽 처리 | A 프로젝트 캐시 도입 | p99 1.2s→180ms | 강 |
| 사내 라이브러리 관리 | — | — | 없음 |

강도는 **강 / 약 / 없음** 셋으로만 나눈다. 중간을 두면 자기합리화가 들어간다.

- **강** — 이력서 상단으로 올린다
- **약** — 남기되 순서를 뒤로
- **없음** — 억지로 만들지 않는다

### 3단계 — 공백 처리

'없음' 칸이 나왔을 때:

1. **인접 경험으로 대체** — "Kafka 경험 없음"이라면 다른 비동기 메시징(SQS, Redis Pub/Sub) 경험을 앞세운다. 문제의 성격이 같다는 걸 보여준다.
2. **학습 중이면 증거와 함께** — "공부 중입니다"만 쓰면 마이너스다. 사이드 프로젝트, 저장소, 정리한 글 같은 물증이 있을 때만 적는다.
3. **아니면 그냥 비운다.** 필수 요건 중 '없음'이 절반을 넘으면 이력서 문제가 아니라 지원처 선택 문제다.

없는 경험을 만들어내는 것만은 절대 안 된다. 매칭 테이블은 면접에서 그대로 질문지가 된다.

### 4단계 — 재배치

바꾸는 것:

- **헤드라인** — 공고의 직무 정의에 맞춘 한 문장으로 교체
- **요약 태그 2개** — '강' 판정 경험 위주로 근거 불릿 교체
- **프로젝트 순서** — 관련도 높은 것을 위로. (시간순이 원칙이지만 관련도가 이긴다)
- **프로젝트 내부 불릿 순서** — 매칭되는 항목을 첫 줄로
- **기술 스택 '주력'** — 공고 필수 기술을 앞에
- **트러블슈팅 선별** — 6개 중 공고와 맞는 3~4개만 남긴다

바꾸지 않는 것:

- 사실, 숫자, 기간, 프로젝트명
- 문서 전체 구조
- 안 쓴 기술을 스택에 추가하는 것

### 5단계 — 키워드 정합

공고의 표기를 따른다. 시스템 필터를 쓰는 회사도 있고, 무엇보다 읽는 사람이 자기 표현을 찾는다.

- 공고가 `Spring Boot`라면 `스프링부트`가 아니라 `Spring Boot`
- 공고가 `백엔드 개발자`라면 `서버 개발자`가 아니라 `백엔드 개발자`

단, **표기만 맞추고 문장은 베끼지 않는다.** 공고 문장을 그대로 옮겨 붙인 이력서는 바로 티가 난다.

## 파일 관리

```
이름_이력서_회사명_YYYYMMDD.pdf
```

버전이 늘어나면 회사별로 뭘 강조했는지 잊어버린다. 매칭 테이블을 회사별로 남겨두면 면접 준비 자료가 그대로 된다.

---

## 커스터마이징 체크리스트

- [ ] 공고 주요 업무의 상위 3개가 이력서 첫 화면에 드러난다
- [ ] 매칭 테이블에서 '강' 판정 경험이 전부 상단에 있다
- [ ] '없음' 항목을 억지로 채우지 않았다
- [ ] 기술 표기가 공고와 일치한다
- [ ] 공고 문장을 그대로 옮긴 곳이 없다
- [ ] 지원 회사와 무관한 프로젝트가 상단에 남아 있지 않다
- [ ] 파일명에 회사명이 들어가 있다
- [ ] **다른 회사 이름이 남아 있지 않다** — 가장 흔하고 가장 치명적인 실수

## 제출 전 교차 검증 (선택)

원티드 이력서 코칭 에이전트(무료, 하루 3회)에 완성본을 넣어본다 — 국내에서 유일하게 실제 합격 이력서 데이터로 포지션별 첨삭을 주는 도구다. 이 스킬의 규칙과 다른 지적이 나오면 그대로 반영하지 말고 사용자에게 보여주고 판단을 받는다 (특히 프로필의 표기 규칙과 충돌하는 과장 제안은 거부). 원티드 지원 건이면 특히 권장.
